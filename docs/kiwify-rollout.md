# Kiwify rollout — Hermes Pro

## Current architecture

- Product files are generated by the Hermes factory and stored in Supabase Storage.
- Product records and sale events are stored in the active Supabase project.
- Kiwify sends order lifecycle events to the Hermes API.
- Hermes sales reporting reads persisted webhook events; it does not estimate sales or profit.

## Webhook URL and authentication

Register this exact HTTPS endpoint in Kiwify Apps → Webhooks:

`https://hermes-pro-api-commercial.onrender.com/api/v1/webhooks/kiwify`

In Kiwify, put the same random signing token already configured as `KIWIFY_WEBHOOK_TOKEN` in Render into the webhook **Token** field.
Do not append `?token=...` to the URL. Kiwify appends `?signature=...` to each delivery.
Hermes verifies HMAC-SHA1 over the exact raw request body with constant-time comparison. The token must never be committed to Git or placed in frontend JavaScript.

Recommended triggers:
- `compra_aprovada`
- `compra_recusada`
- `compra_reembolsada`
- `chargeback`
- `pix_gerado` and `boleto_gerado`
- For subscriptions only: `subscription_renewed`, `subscription_late`, `subscription_canceled`

The receiver deduplicates order/event identities. Kiwify can retry failed deliveries; acknowledge with 2xx only after persistence.

## Product publishing

The Kiwify API supports reading products and managing webhooks, but does not expose a product-creation or file-upload endpoint in the current product API reference. Product creation, pricing, guarantee, support contact, and delivery configuration remain in the Kiwify dashboard.

For each product:
1. Review the PDF and cover in Hermes Studio.
2. Create the digital product in Kiwify.
3. Upload the PDF or configure Kiwify's Member Area and delivery.
4. Set the price, guarantee, support contact, and checkout details.
5. Copy the official checkout URL from the Kiwify product Links tab.
6. Open Hermes → Publicação, select the ebook in `ready_to_publish`, and save the checkout URL.
7. Check Kiwify's delivery log and verify the resulting event in Hermes.

Hermes stores the checkout under `metadata.publications.kiwify` with `verified=false` until a real checkout/purchase confirmation exists. Never mark a sale as approved without a confirmed Kiwify event.

## Test and replay

Use Kiwify's **Testar Webhook** panel to validate signature and delivery. Its order IDs are fictitious; the resulting event is a test, not real revenue. Inspect the Kiwify delivery log for a 2xx response. Re-send failed events after the receiver is healthy.


## AI cover generation

New product jobs use OVHcloud AI Endpoints with Stable Diffusion XL 1.0 by default:
- `AI_IMAGE_PROVIDER=ovhcloud`
- `AI_IMAGE_REQUIRED=true`
- `OVHCLOUD_IMAGE_MODEL=stable-diffusion-xl-base-v10`
- `OVHCLOUD_IMAGE_TIMEOUT_SECONDS=90`

No API key, account, payment method, or card is required for anonymous calls. OVHcloud documents an anonymous limit of 2 requests per minute per IP and model; Hermes serializes requests with a 35-second minimum gap and retries a 429 once using the provider's `Retry-After` value. The generated 1024x1024 artwork is composed with Hermes typography into a 1600x2560 PNG cover and stored in private Supabase Storage. The four internal illustrations remain topic-specific infographics rendered from the writer's illustration briefs. Kiwify publication requires a verified AI-generated cover.

The SDXL 1.0 model is published under CreativeML OpenRAIL++; commercial use is subject to that license's restrictions. OVHcloud's AI Endpoints documentation states that request data is not stored or shared during or after model use. Prompts contain only public ebook subject material. See https://www.ovhcloud.com/en-ie/public-cloud/ai-endpoints/catalog/stable-diffusion-xl/, https://docs.ovhcloud.com/en/guides/public-cloud/ai-machine-learning/ai-endpoints-troubleshooting, and https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0.

AI Horde remains an optional provider via `AI_IMAGE_PROVIDER=aihorde`, but anonymous queue priority can be too slow for production. A local vector fallback is available only when `AI_IMAGE_REQUIRED=false`; such a product is intentionally not eligible for Kiwify publication until an AI cover has been generated.

## Commercial copy package

Before a product can pass the Kiwify publication gate, the factory also generates and validates a `marketing_pack` from the approved manuscript: long and short descriptions, target audience, concrete benefits, contents list, FAQ, search keywords, and three ready-to-edit social posts. The copy gate rejects guaranteed-income or guaranteed-results claims and blocks publication when the package is missing or structurally incomplete. These assets are prepared for the Kiwify listing and social distribution; they are not evidence that a social post was published.


## Private artifact link lifecycle

Ebook files remain in private Supabase Storage buckets. Product metadata stores the stable bucket/object path separately from its short-lived signed URL. The API refreshes signed URLs automatically when they are within 24 hours of expiry and persists the new URL, so a dashboard refresh does not leave old PDF/DOCX/cover links broken. Files are never made public.


The anonymous queue was checked against the live AI Horde model-status endpoint. SDXL 1.0 can be heavily backlogged for anonymous requests; the default was therefore changed to Stable Diffusion 2.1, which had available volunteer workers and no queued jobs at the time of verification. The provider remains configurable with `AI_HORDE_MODEL`.
