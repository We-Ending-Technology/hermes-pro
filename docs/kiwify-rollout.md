# Kiwify rollout — Hermes Pro

## Current architecture

- Product files are generated by the Hermes factory and stored in Supabase Storage.
- Product records and sale events are stored in the active Supabase project.
- Kiwify sends order lifecycle events to the Hermes API.
- Hermes sales reporting calculates revenue only from persisted payment events; it does not estimate sales.

## Webhook

Configure the existing Kiwify webhook in Apps → Webhooks to send JSON POST events to the endpoint URL supplied by the Hermes operator.

Enable at minimum:
- Purchase approved
- Refund
- Chargeback
- Subscription renewed (only when selling subscriptions)

The endpoint is protected by the KIWIFY_WEBHOOK_TOKEN Render environment variable. Do not commit its value to Git or expose it in frontend JavaScript.

## Product publishing

The current Kiwify integration receives and reconciles sales webhooks. It does not create a Kiwify product, set its price, upload course content, or generate checkout links automatically.

For each product:
1. Review the PDF and cover in Hermes Studio.
2. Create the digital product in the Kiwify dashboard.
3. Upload the PDF or configure Kiwify's member area and delivery method.
4. Set price, guarantee, support contact, and checkout details.
5. Copy the official checkout URL into the product publication record when the product publication UI/API is enabled.
6. Test the Kiwify webhook and verify that the matching sale event appears in Hermes.

Never mark a product as published or a sale as approved without confirmation from Kiwify.
